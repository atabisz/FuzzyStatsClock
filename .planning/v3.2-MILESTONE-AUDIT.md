## Tech Debt

### Phase 41: PhraseEngine Forward-Integration Gap

`PhraseStyleChanged` handler in `MainWindow.OpenSettings()` (line 354) stores `_currentPhraseStyle` and calls `SaveSettings()` but does **not** call `PhraseEngine.SetLocale()`. The locale key format (`"en-classic"`) also differs from the settings string (`"Classic"`), so a mapping will be needed.

**Impact today:** None — only one provider (`EnglishPhraseProvider`) is registered, so no locale swap is possible regardless.

**Impact at Phase 45:** When Terse/Poetic/Rude providers are registered, switching phrase style in the Settings window will persist the selection but the live widget will continue showing Classic phrases until the app restarts (where `ApplySettings()` would need to call `SetLocale()` too). This wiring must be added in Phase 45.

**Recommended fix for Phase 45:** In `OpenSettings()`, update the `PhraseStyleChanged` handler to map the style name to a locale key and call `PhraseEngine.SetLocale()`. Update `ApplySettings()` similarly.

### Phase 43: Two bugs fixed during audit

Both were found during integration check and fixed before this audit was committed:

- **Settings controls not refreshing after theme applied** (commit `e095ebc`): `RefreshControls()` added to `SettingsWindow`; called from `ThemeSelected` handler after `ApplyNamedTheme()`.
- **Scroll-wheel opacity not clearing active theme** (commit `eaf6a17`): `ClearActiveTheme()` added to `Window_PreviewMouseWheel` before `SaveSettings()`.
