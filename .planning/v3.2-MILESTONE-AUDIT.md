## Tech Debt

### Phase 41: PhraseEngine Forward-Integration Gap

`PhraseStyleChanged` handler in `MainWindow.OpenSettings()` stores `_currentPhraseStyle` and calls `SaveSettings()` but does **not** call `PhraseEngine.SetLocale()`. The locale key format (`"en-classic"`) also differs from the settings string (`"Classic"`), so a mapping will be needed.

**Impact today:** None — only one provider (`EnglishPhraseProvider`) is registered.

**Impact at Phase 45:** When Terse/Poetic/Rude providers are registered, switching phrase style in Settings will persist the selection but the live widget will continue showing Classic phrases until the app restarts. This wiring must be added in Phase 45.

**Recommended fix for Phase 45:** In `OpenSettings()`, update `PhraseStyleChanged` to map the style name to a locale key and call `PhraseEngine.SetLocale()`. Update `ApplySettings()` similarly.

### Phase 42: SettingsService.Defaults() consistency

`SettingsService.Defaults()` does not explicitly set `Theme` or `PhraseStyle` fields — both rely on `AppSettings` record `init` defaults. `ResetToDefaults()` in MainWindow handles reset correctly by calling `SetTextStyle("Classic")` directly, so no current requirement is affected. New AppSettings fields should be added to both the record default and `Defaults()` factory to prevent future drift.

**Severity:** Non-blocking. Recommend addressing in a future polish phase.
