# Phase 79 — UI Design Contract

> Visual and interaction contract for the **TempsText** line on the widget (`MainWindow`).
> Generated by gsd-ui-researcher, consumed by gsd-planner + gsd-executor + gsd-ui-auditor.
>
> **Platform reality:** This is a WPF desktop widget on .NET 10, Windows-only. There is no React, no CSS, no Figma, no shadcn registry. The "design system" is the existing `MainWindow.xaml` — a transparent frameless overlay whose colored text is driven by the user-customizable **accent color** (5 presets + custom picker + auto-contrast brightness adjust). All styling values below are derived byte-for-byte from the **UptimeText** precedent at `MainWindow.xaml:277-284`; this spec binds TempsText to exact clone parity with UptimeText so the widget's visual rhythm stays uniform.
>
> **The contract:** TempsText is a near-clone of UptimeText — same FontFamily, same FontSize, same Margin, same TextAlignment, same design-time Foreground, same Visibility default. The only differences are the `x:Name` identifier (`TempsText`), the initial Text (`""` empty vs `"up —"` placeholder), and the runtime value source (`TemperatureFormatter.Format(...)` vs uptime computation). This matches CONTEXT D-15 verbatim.

## Spacing Scale

Declared values (all multiples of 2, primarily multiples of 4; inherited from the existing widget layout — **no new spacing tokens introduced by Phase 79**):

| Token | Value | Usage on TempsText |
|-------|-------|---------------------|
| row-gap | 2px | Top margin between stat-panel rows — TempsText inherits the existing stat-row rhythm (`Margin="0,2,0,0"` — same as CpuRow, GpuRow, MemRow, PagRow, BattRow, UptimeText) |
| container-top | 8px | StatsPanel's own top margin (existing `StatsPanel Margin="0,8,0,0"`) — unchanged by Phase 79 |

**Exceptions:** None. Phase 79 adds exactly one new element. That element's margin is `0,2,0,0` — identical to every other row in `StatsPanel`. No new spacing token is introduced; no existing margin is changed.

**Why 2px and not 4px or 8px:** The entire StatsPanel uses 2px inter-row spacing as a deliberate compactness choice (6 stat rows stacked inside a 184px-wide panel on a desktop overlay). The widget prioritizes information density over breathing room; changing this rhythm for TempsText would visually orphan the new row. Clone the 2px gap.

## Typography

The widget uses a small palette of inline Foreground/FontSize overrides. TempsText uses exactly **one** role — the "secondary stat line" role already established by UptimeText.

| Role | Element(s) | Size | Weight | Font Family | Foreground (design-time) | Foreground (runtime) | Source |
|------|-----------|------|--------|-------------|--------------------------|----------------------|--------|
| Primary stat label | CpuLabel / GpuLabel / MemLabel / PagLabel / BattLabel | 12px | Regular (Light face) | Segoe UI Light | `White` | `_accentColor` via ApplyDisplayColor + ApplyTheme | xaml:177, 198, 219, 240, 261 |
| Primary stat value | CpuText / GpuText / MemText / PagText / BattText | 12px | Regular (Light face) | Segoe UI Light | `White` | `_accentColor` via ApplyDisplayColor + ApplyTheme | xaml:187, 208, 229, 249, 270 |
| **Secondary stat line** | **UptimeText / TempsText** | **11px** | **Regular (Light face)** | **Segoe UI Light** | **`White`** | **`_accentColor` via ApplyDisplayColor + ApplyTheme** | xaml:277-284 (UptimeText); new for TempsText |

**Why 11px and not 12px:** UptimeText already uses 11px as a visual-rank signal — it carries ancillary info (rolling averages, uptime, process count) rendered at a slightly smaller size than the primary CPU/GPU/MEM/PAG/BATT percentage bars above it. TempsText is the SAME information class (ancillary system telemetry, presented as a compact inline string rather than a value+bar). Using 11px keeps it ranked below the bar rows and visually paired with UptimeText. Using 12px would promote it to the rank of the bar rows and break the visual hierarchy.

**Weight:** `Segoe UI Light` is the explicit font family across the entire widget (all 11 existing FontFamily declarations in MainWindow.xaml name "Segoe UI Light"). There is no weight override anywhere — the Light face is the weight. TempsText MUST use `FontFamily="Segoe UI Light"` to match.

**Line height:** WPF default (not explicitly set anywhere in MainWindow.xaml). The `Margin="0,2,0,0"` token provides all vertical spacing; line height is unmodified.

**No new font sizes, no new weights, no new font families introduced by Phase 79.** TempsText reuses exactly one existing role.

## Color

The widget uses a **runtime-driven color model** — every colored text element has a design-time `Foreground="White"` placeholder that is overwritten on first `ApplyDisplayColor` / `ApplyTheme` invocation with a fresh `new SolidColorBrush(_accentColor)`. The accent color is user-customizable (5 presets: Cyan / Amber / Green / Magenta / White + custom picker) and dynamically adjusted by the auto-contrast subsystem (Phase 33) based on screen content luminance. There is **no theming** — there is only the accent color and its dimmed 55%-alpha derivative used for secondary text (QualifierText, DateText).

| Role | Value | Usage on TempsText |
|------|-------|---------------------|
| Dominant (60%) | `Transparent` | Widget background — TempsText sits on the transparent overlay; no direct usage |
| Secondary (30%) | Hover-backdrop `#59000000` (Phase 14) | Semi-opaque black rectangle that appears behind the widget text on hover — TempsText participates visually (it sits over the backdrop) but has no direct background assignment |
| Accent (10%) | `_accentColor` (user-chosen RGB; default Cyan `#FF00FFFF`) | **TempsText.Foreground** at runtime — assigned fresh `new SolidColorBrush(_accentColor)` in both `ApplyDisplayColor` (xaml.cs:1674) AND `ApplyTheme` (xaml.cs:1637) |
| Destructive / alert | `#FFFF4444` (BattBar only, when `_batteryAlertActive=true`) | Not used by TempsText. No temperature-threshold alert in Phase 79 (future requirement). |
| Design-time default | `"White"` (literal XAML attribute) | Initial TempsText.Foreground before first `ApplyDisplayColor` call. Identical to UptimeText's xaml-declared default. Never observable at runtime (overwritten in the same tick). |

**Accent reserved for (elements that receive `_accentColor` as full-opacity foreground):**

- `PhraseText` (primary clock phrase in Phrase mode)
- `EmphasisText` (primary clock phrase hour word)
- `HourHand` / `MinuteHand` / dial ticks / dial minute dots / dial hour numbers (Dial mode)
- `CpuBar` / `GpuBar` / `MemBar` / `PagBar` / `BattBar` (fill bars — `Background`, not `Foreground`)
- `CpuLabel` / `GpuLabel` / `MemLabel` / `PagLabel` / `BattLabel` (stat row labels)
- `CpuText` / `GpuText` / `MemText` / `PagText` / `BattText` (stat row values)
- `UptimeText` (secondary stat line)
- **`TempsText` — NEW for Phase 79 (secondary stat line, same role as UptimeText)**

**Accent-dimmed (55% alpha / `#8C`) reserved for:**

- `QualifierText` (Phrase mode qualifier)
- `DateText` (date row)

**Not used by TempsText:** no dimmed variant, no alert/destructive color, no distinct per-segment color. A CPU reading at 90° renders in the same color as a CPU reading at 40° in Phase 79. (Future milestone: threshold alerts per REQUIREMENTS.md "Temperature thresholds / alerts".)

**Auto-contrast participation (TEMP-LINE-06):** `ContrastRefreshController` (Phase 33) samples the pixels behind the widget every 500ms, computes WCAG luminance, and adjusts `_accentColor` up to ±40 HSL steps to maintain a 4.5:1 contrast ratio. The controller's per-tick work is to **re-run `ApplyDisplayColor` with the contrast-adjusted color**. Because Phase 79 extends `ApplyDisplayColor` with `TempsText.Foreground = brush;`, auto-contrast participation is automatic — no new controller wiring, no new subscription.

## Copywriting Contract

TempsText displays a runtime-formatted string produced by `TemperatureFormatter.Format(...)` (shipped Phase 76, `FuzzyClock.Core/TemperatureFormatter.cs`). There is no static copy owned by Phase 79 — every character on the line is output of the Phase 76 formatter. The formatter's output shape is locked by REQUIREMENTS.md TEMP-LINE-02, TEMP-LINE-03, TEMP-LINE-04.

| Element | Copy | Source |
|---------|------|--------|
| Full-line example (all 4 sensors visible + readable) | `CPU 52°  GPU 61°  Mobo 38°  NVMe 41°` | TEMP-LINE-02 (format), TEMP-LINE-03 (friendly labels) |
| Dev-box example (Phase 75 spike baseline — only GPU readable) | `GPU 51°` | CONTEXT D-19 + Phase 75 spike Section 3 |
| All-suppressed (formatter returns empty → line collapsed) | `""` (empty string; TempsText.Visibility = Collapsed per D-03) | CONTEXT D-03 + formatter contract |
| CPU segment shape | `CPU {int}°` | TemperatureFormatter.cs:37 |
| GPU segment shape | `GPU {int}°` | TemperatureFormatter.cs:38 |
| Mobo segment shape | `Mobo {int}°` | TemperatureFormatter.cs:39 — **not** `MOBO`, **not** `Motherboard`, **not** `MB` |
| NVMe segment shape | `NVMe {int}°` | TemperatureFormatter.cs:40 — **not** `NVME`, **not** `SSD`, **not** `Storage` |
| Segment separator | 2 spaces (`"  "`) | TEMP-LINE-02 — `string.Join("  ", segments)` in formatter |
| Temperature suffix | `°` only (degree sign, U+00B0) — no `C`, no `F`, no space between integer and degree | TEMP-LINE-02 ("no C/F suffix, no unit toggle") + formatter line 37-40 |
| Rounding | Banker's rounding via `(int)Math.Round(value)` | TemperatureFormatter.cs:37-40 |
| Suppressed-segment visibility | N/A segments (`-1f`) and per-sensor-toggle-off segments are silently omitted from the line — the remaining segments reflow naturally with no placeholder, no `(N/A)`, no trailing separator | TEMP-LINE-04 + formatter guard `>= 0f` |

**Design-time XAML placeholder:** `Text=""` (empty string). CONTEXT D-15 locks this. Rationale: (1) the first stats-tick runs within ~100ms of widget visibility and overwrites `Text` immediately, so users never see the placeholder; (2) an empty string paired with `Visibility="Visible"` produces zero visual footprint for the ~100ms window (unlike a placeholder like `"—"` which would flicker); (3) matches the "no visible flash" principle documented for UptimeText's `"up —"` placeholder (UptimeText's placeholder is visible in one legitimate circumstance — before StatsService finishes async init — but TempsText has no equivalent latency since `TemperatureFormatter.Format` is a synchronous pure function and can be called on the very first tick).

**No primary CTA** — the widget has no CTAs; it is display-only. (Right-click opens the tray menu per Phase 77, but that's a menu invocation, not widget-owned copy.)

**No empty state copy** — when the formatter returns `""`, the TextBlock collapses (`Visibility=Collapsed` per D-03). No "no temperatures available" placeholder is shown. Rationale: the user has already opted in to the Temps line via the Settings master toggle; a collapsed line is the correct signal that their current hardware + per-sensor choices yielded nothing this tick. Adding a placeholder would (a) contradict the widget's minimalist information-density principle and (b) produce a visually broken stripe when all sensors are N/A.

**No error state copy** — N/A is a hardware-availability fact (Phase 75 locked `-1f` as the N/A sentinel; init failure is silent per Phase 75 D-14). The formatter treats `-1f` as "omit this segment"; there is no user-facing error surface.

**No destructive actions** — Phase 79 has no destructive controls. Toggling a temp source off in Settings is reversible and non-destructive.

### Attribute-by-attribute derivation

| Attribute | Value | Why |
|-----------|-------|-----|
| `x:Name` | `TempsText` | Code-behind handle for `TempsText.Text`, `TempsText.Visibility`, `TempsText.Foreground`. Naming convention: match the `{kind}Text` pattern (`CpuText`, `GpuText`, `MemText`, `PagText`, `BattText`, `UptimeText`, `DateText`) — TempsText is the 8th in the family. |
| `Margin` | `0,2,0,0` | Identical to every other stat-panel row — preserves 2px inter-row rhythm. |
| `Visibility` | `Visible` | Design-time default. First tick immediately computes the real visibility via the D-05 predicate `(TempsLineVisible && formatted.Length > 0)`. Starting `Visible` means (a) on `TempsLineVisible=true` + formatter-non-empty, zero visual flash; (b) on `TempsLineVisible=false` or formatter-empty, the first tick collapses it within ~100ms (the only moment where an empty stripe could be visible — imperceptible in practice). Starting `Collapsed` would be technically safer but risks a one-tick gap on the default-ON path if any ordering bug delays the first `UpdateTempsDisplay` call. Starting Visible with empty text is the UptimeText convention (xaml:279 `Visibility="Visible"`) and should be cloned. |
| `FontFamily` | `Segoe UI Light` | Matches UptimeText (xaml:280) and the widget-wide convention. |
| `FontSize` | `11` | Matches UptimeText (xaml:281). Secondary-stat-line rank (smaller than the 12px bar rows). |
| `Foreground` | `White` | Design-time placeholder, overwritten immediately by `ApplyDisplayColor`/`ApplyTheme`. Matches UptimeText (xaml:282). Needed so the Visual Studio XAML designer preview shows readable text instead of invisible transparent text. |
| `Text` | `""` (empty) | First tick overwrites with `TemperatureFormatter.Format(...)` output. Empty-string default has no visible footprint. CONTEXT D-15. |
| `TextAlignment` | `Left` | Matches UptimeText (xaml:284). Stat panel's 184px width comfortably fits the maximum 4-segment line (`CPU 99°  GPU 99°  Mobo 99°  NVMe 99°` ≈ 150px at 11px Segoe UI Light), so left-alignment leaves the right margin white-space rather than forcing centering. Centered alignment would visually conflict with the left-aligned UptimeText directly above. Right-alignment is ruled out by the same precedent. |

### Elements explicitly not added

- **No `Grid` wrapper** — TempsText is a single TextBlock, not a bar-row. No space for a fill bar, no percentage column, no label column. The entire line is one inline string from the formatter.
- **No `Border`** — no per-line backdrop, no rounded corners, no inline card chrome. The widget's sole backdrop is `BackdropBorder` (Phase 48+), which wraps the entire StackPanel — TempsText participates via ancestor inheritance.
- **No `AutomationProperties.*`** — see Accessibility section.
- **No `ToolTip`** — CONTEXT explicitly notes "widget has no hover interaction on individual text elements." The widget's only hover behavior is the global backdrop reveal (Phase 14) and the proximity-fade (Phase 66-69). Individual elements do not surface tooltips.
- **No new `Style` resource** — the widget does not use styles for its colored text (every element uses imperative Foreground assignment). Phase 79 must not introduce a Style; it would be the first such style in the file and would break the "imperative Foreground" convention.

### Visibility predicate (authoritative, per D-05)

```csharp
TempsText.Visibility = (_settings.TempsLineVisible && formatted.Length > 0)
    ? Visibility.Visible
    : Visibility.Collapsed;
```

- `formatted` is the return value of `TemperatureFormatter.Format(...)` — already sitting in a local string inside `UpdateTempsDisplay`.
- **StatsPanel-off case is handled automatically** by WPF layout inheritance: `StatsPanel.Visibility = Collapsed` cascades to TempsText without the predicate needing to reference `_settings.StatsVisible`. This matches the existing UptimeText pattern (comment at xaml:275-276 documents the inheritance).
- **No three-way compound check** (D-06): the widget-side predicate owns two conditions (master + formatter-non-empty); the third (StatsVisible) is inherited via WPF layout tree.

### State matrix

Canonical rendering of each `(TempsLineVisible, StatsVisible, formatter-output)` combination:

| TempsLineVisible | StatsVisible | Formatter output | TempsText.Visibility | User perception |
|------------------|--------------|------------------|----------------------|-----------------|
| false | true | (any) | `Collapsed` (predicate false) | Line absent. |
| false | false | (any) | `Collapsed` (predicate false + parent also Collapsed) | Line absent. Stats panel absent. |
| true | true | `""` (empty) | `Collapsed` (predicate false — length=0) | Line absent. Stat rows visible above. |
| true | true | `"GPU 51°"` (1 segment) | `Visible` (predicate true) | **Rendered line: `GPU 51°` in accent color, 11px Segoe UI Light, below UptimeText.** Dev-box case per D-19. |
| true | true | `"CPU 52°  GPU 61°  NVMe 38°"` (3 segments) | `Visible` | Rendered with 2-space separators, integer degrees, ° only. Per TEMP-LINE-02 format. |
| true | true | `"CPU 52°  GPU 61°  Mobo 38°  NVMe 41°"` (4 segments) | `Visible` | Maximum-width case; fits comfortably in StatsPanel's 184px at 11px Segoe UI Light. |
| true | false | (any — UpdateTempsDisplay can still write to `.Text` even when Collapsed) | `Collapsed` via parent StatsPanel inheritance (even if local predicate is Visible) | Line absent (whole stats panel absent). |
| true | true | `"CPU 52°"` (1 segment — other 3 suppressed by per-sensor toggle) | `Visible` | Only CPU segment rendered. Reflow is free — no trailing separator, no placeholder. |

**Transition ordering:** `UpdateTempsDisplay` sets `.Text` FIRST, then `.Visibility`. This prevents a one-frame gap where a newly-visible TextBlock still holds stale prior-tick text. The Text-before-Visibility discipline matches the existing UpdateStatsDisplay pattern (xaml.cs:772 sets `.Text`; visibility is gated by the SetUptimeRowVisible helper separately).

### Non-interactions (by design)

- **TempsText is not clickable.** The widget's mouse event wiring lives on the root `<Window>` (drag via `MouseLeftButtonDown`, right-click tray menu via `PreviewMouseRightButtonUp` per Phase 77); individual stats-panel elements do not handle mouse events. TempsText has no `MouseDown` / `MouseEnter` / `MouseLeave` / `Click` handlers.
- **TempsText is not keyboard-focusable.** The widget has no keyboard focus (the overlay runs with `WS_EX_NOACTIVATE` conceptually — see Phase 25/26 click-through plumbing; keyboard focus is never on the widget). WPF's default `Focusable="False"` for TextBlock is inherited.
- **TempsText does not participate in drag.** Dragging the widget fires on the root Window's mouse-down; TempsText sits inside the dragged surface but does not itself handle the event.
- **TempsText does not freeze on menu-open (Phase 77).** The Phase 77 `_menuOpen` guard prevents `Opacity` changes during right-click menu display, but per-tick value updates to `.Text` / `.Visibility` continue — the menu is a ContextMenuStrip overlay, not a widget-state freeze. TempsText continues to refresh silently behind the menu.
- **TempsText does not have a hover tooltip.** See "Elements explicitly not added" above.

## Code-Behind Contract (binding to the planner)

### New private method

```csharp
private void UpdateTempsDisplay()
{
    float cpu  = _temperatureService?.CpuTempC  ?? -1f;
    float gpu  = _temperatureService?.GpuTempC  ?? -1f;
    float mobo = _temperatureService?.MoboTempC ?? -1f;
    float nvme = _temperatureService?.NvmeTempC ?? -1f;

    string formatted = TemperatureFormatter.Format(
        cpu, gpu, mobo, nvme,
        _settings.TempCpuVisible,
        _settings.TempGpuVisible,
        _settings.TempMoboVisible,
        _settings.TempNvmeVisible);

    TempsText.Text = formatted;
    TempsText.Visibility = (_settings.TempsLineVisible && formatted.Length > 0)
        ? Visibility.Visible
        : Visibility.Collapsed;
}
```

- Null-coalesce `_temperatureService?. ... ?? -1f` mirrors the existing `GetCurrentSettingsSnapshot` pattern at xaml.cs:415-419 (Phase 78 D-01 defensive-null convention).
- Method is `private void`, takes no parameters, reads instance state directly. Matches `UpdateStatsDisplay` / `UpdateUptimeDisplay` / `UpdateDateDisplay` shape.
- Foreground is **not** set here — it's set in `ApplyDisplayColor` / `ApplyTheme`. The per-tick path only touches `.Text` + `.Visibility`.
