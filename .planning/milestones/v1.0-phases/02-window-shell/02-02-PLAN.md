    **App.xaml** — Remove StartupUri entirely. The window is created manually in OnStartup:

    ```xml
    <Application x:Class="FuzzyClock.App.App"
                 xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"
                 xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"

    </Application>
    ```

    **App.xaml.cs** — Full implementation with:
    - Named Mutex "FuzzyClock_SingleInstance_v1" checked in OnStartup before any window is created
    - If Mutex not acquired (createdNew=false): dispose Mutex, call Shutdown(), return immediately
    - Hidden owner window: Width=0, Height=0, WindowStyle=ToolWindow, ShowInTaskbar=false, Visibility=Hidden. Call owner.Show() before setting Owner — the hidden owner must be shown for ownership to work
    - Create MainWindow, set mainWindow.Owner = hiddenOwner, then call mainWindow.Show()
    - Store _instanceMutex as a field; release it in OnExit override (ReleaseMutex + Dispose)
    - Call base.OnStartup(e) AFTER the Mutex check passes but BEFORE creating windows

    Namespace: FuzzyClock.App
    Class: partial class App : Application

    Do NOT use Application.Current.MainWindow — let WPF track the main window automatically. Do NOT put any phrase logic or clock logic here.

    Why the hidden owner trick: ShowInTaskbar=False alone does not suppress the overlay from the Alt+Tab switcher. Setting a hidden ToolWindow as Owner is the pure-WPF pattern that suppresses both taskbar and Alt+Tab presence.

    Why Mutex before window creation: A second launch that briefly shows a window before closing it would flash a second overlay. The Mutex check must be the first thing in OnStartup.

    **MainWindow.xaml** — Transparent overlay window with the following required properties set in XAML (NOT in code-behind — AllowsTransparency cannot be changed after the window handle is created):

    Window attributes:
    - x:Class="FuzzyClock.App.MainWindow"
    - WindowStyle="None" (removes OS chrome, required for AllowsTransparency)
    - AllowsTransparency="True" (per-pixel alpha, must be paired with WindowStyle=None)
    - Background="Transparent" (window client area is transparent)
    - Topmost="True" (always above all other windows, unconditional per user decision)
    - ShowInTaskbar="False" (no taskbar button)
    - SizeToContent="WidthAndHeight" (window auto-sizes to text content)
    - WindowStartupLocation="Manual" (position set in code-behind via ContentRendered)
    - ResizeMode="NoResize"
    - Include mc:Ignorable="d" and the standard blend/mc namespaces for tooling compatibility

    Root Grid:
    - Background="#01000000" (alpha=1, RGB=black — near-transparent but hit-testable, essential for right-click to work over transparent pixels)
    - Attach ContextMenu with a single MenuItem: Header="Close", Click="CloseMenuItem_Click"

    TextBlock inside the Grid:
    - x:Name="PhraseText"
    - Text="half past 3" (static placeholder for Phase 2 — phrase engine NOT wired yet)
    - FontFamily="Segoe UI Light"
    - FontSize="32"
    - Foreground="White"
    - Margin="8" (breathing room so the drop shadow is not clipped)
    - DropShadowEffect (via TextBlock.Effect): Color="Black", BlurRadius="6", ShadowDepth="2", Opacity="0.8", Direction="315"

    Why DropShadowEffect is essential: ClearType sub-pixel anti-aliasing is disabled by Windows DWM on transparent HWND surfaces. WPF falls back to greyscale AA, making text appear soft. The drop shadow provides the visual definition that ClearType would normally supply.

    Why #01000000 background: A fully transparent Background (alpha=0) has no hit-test surface — mouse events pass through to the window below, breaking right-click. Alpha=1 is imperceptible visually but makes the surface mouse-interactive.

    **MainWindow.xaml.cs** — Code-behind with:
    - Constructor: InitializeComponent() then subscribe ContentRendered += (_, _) => PositionTopRight()
    - PositionTopRight() method: const double Padding = 20.0; Left = SystemParameters.PrimaryScreenWidth - ActualWidth - Padding; Top = Padding;
    - CloseMenuItem_Click handler: Application.Current.Shutdown() — NOT this.Close() (hidden owner window keeps process alive if Close() is used)

    Why ContentRendered for positioning: SizeToContent=WidthAndHeight defers measurement until after the layout pass. ActualWidth is 0 in the constructor before Show() is called. ContentRendered fires after the first layout pass when ActualWidth is valid.
