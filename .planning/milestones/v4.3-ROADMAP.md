# Milestone v4.3: Configurable Ghost Override

**Status:** ✅ SHIPPED 2026-05-07

## Overview

Let users customize which modifier keys suppress Ghost Mode instead of hardcoded Ctrl+Alt. Users can now choose any combination of Left Ctrl, Left Alt, and Left Shift via Settings > Behavior, with init defaults (Ctrl+Alt) preserving v4.2 upgrade behavior.

**Key Decisions:**

1. **Four-phase structure** — Foundation (Phase 81) → parallel UI+Controller (Phase 82+83) → Integration (Phase 84); enabled parallel execution of phases 2 and 3
2. **Init-property defaults (true, true, false)** — Preserves Ctrl+Alt behavior for users upgrading from v4.2; explicit init defaults prevent JSON absent-field false-default issue
3. **Left-side VK codes only** — VK_LCONTROL, VK_LMENU, VK_LSHIFT prevent AltGr false-positives on EU keyboards (v2.3 lesson)
4. **All-unchecked = override disabled** — Clear semantics: all-false means ghost always activates regardless of held keys
5. **AND logic (not OR)** — When multiple modifiers enabled, ALL must be held simultaneously to suppress ghost; prevents single-key sensitivity issue
6. **UpdateModifierConfig property setter** — Controller gets public method called from ApplySettings + event handlers; instant config changes without controller recreation
7. **IsModifierHeld() public for testing** — Renamed from IsCtrlAltHeld, made public for direct unit testing; 8 parametric DataRow tests cover all 2³ combinations
8. **Short-circuit all-false in OnTimerTick** — When all three bools false, skip IsModifierHeld call entirely; satisfies DET-02 via never calling method when disabled

**Issues Resolved:**

- Hardcoded Ctrl+Alt limitation from v2.3 Ghost Mode now configurable (user request)
- Single-key sensitivity avoided via AND logic requirement (DET-03)
- AltGr false-positive risk mitigated via left-side VK codes (DET-05)
- v4.2 upgrade path preserved via init defaults (CFG-04)
