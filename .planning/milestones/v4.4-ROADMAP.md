# Milestone v4.4: Smooth Ghost Fade Under Load

**Status:** ✅ SHIPPED 2026-05-21
**Phases:** 85–87
**Total Plans:** 8
**Test baseline:** 574 → 587 (+13)
**Tag:** v4.4

## Overview

Made ghost-mode proximity fade visibly smooth under sustained CPU contention (~25–50%) by decoupling sampling cadence from rendering cadence and moving the sampling loop off the UI thread — without changing any user-visible interaction semantics or persisted settings. Three sequential phases: refactor `GhostModeController` so sampling runs on a thread-pool timer (Phase 85), introduce frame-driven opacity rendering in `MainWindow` so the visible fade glides at display refresh rate (Phase 86), then verify with new pure-static unit tests, the existing regression suite, and a manual CPU-load smoothness run (Phase 87).

## Phases

### Phase 85: Off-thread sampling refactor

**Goal**: `GhostModeController` samples cursor position, computes proximity ratio, and emits target-ratio updates without occupying the UI thread, while preserving every existing ghost interaction semantic (terminal-state ghost activation/restore, modifier override, drag/menu/settings guards observed downstream).
**Depends on**: Nothing (first phase of milestone — continues from Phase 84)
**Requirements**: SAMP-01, SAMP-02, SAMP-03, SAMP-04, SEM-01, SEM-02, SEM-03, SEM-05
**Plans**: 4 plans

Plans:

- [x] 85-01: Pure tickable seam — `SampleResult` struct, `GhostTransition` enum, `OnSampleTick` method (no threading change yet)
- [x] 85-02: Volatile config fields — `_isEnabled`, `_useCtrl/Alt/Shift`, `_ghostFadeRadiusPx`, `_isGhostMode` (cross-thread coherence prep)
- [x] 85-03: Off-thread timer — `System.Threading.Timer` + `Interlocked` reentrancy guard + `Dispatcher.BeginInvoke` marshalling
- [x] 85-04: Synchronous disposal — `_timer.Dispose(WaitHandle)` blocks until in-flight tick drains; closes the teardown race in both directions

**Details:**

Replaced the UI-thread `DispatcherTimer` with a `System.Threading.Timer` running at 33 ms cadence. `GetCursorPos`, `GetWindowRect`, `GetAsyncKeyState`, and the pure ratio computation now run on the sampling thread; UI-touching work (`WS_EX_TRANSPARENT` toggle, `Activate`/`Restore`, `ProximityChanged` and `Restored` event raises) marshals via `Dispatcher.BeginInvoke`. Reentrancy guarded with `Interlocked.Exchange(ref _tickInFlight, ...)`. Dispatcher-shutdown guard (`HasShutdownStarted/HasShutdownFinished`) closes the late-`BeginInvoke`-into-torn-down-window race; synchronous disposal (`ManualResetEvent` + `_timer.Dispose(notifyObject)` + `WaitOne()`) closes the in-flight-tick-survives-Dispose race. Pure tickable seam (`internal SampleResult OnSampleTick(int cursorX, int cursorY, int rectLeft, int rectTop, int rectRight, int rectBottom, bool modifiersHeld)` returning a `GhostTransition` enum) makes the threading machinery test-irrelevant.

### Phase 86: Frame-driven opacity rendering

**Goal**: The visible fade traversal glides at display refresh rate via a per-frame lerp pump driven by `CompositionTarget.Rendering`, fully decoupled from sampling cadence, with all `MainWindow` interaction guards (drag, settings window, right-click menu, mouse-wheel opacity) preserved verbatim.
**Depends on**: Phase 85 (consumes `ProximityChanged` as target-ratio source)
**Requirements**: FADE-01, FADE-02, FADE-03, FADE-04, SEM-04
**Plans**: 2 plans

Plans:

- [x] 86-01: `GhostModeController` surface — `EnabledChanged` event with change-detect setter + `internal static LerpRatio` helper with terminal-state snap
- [x] 86-02: `MainWindow` render pump — rename `_proximityRatio` → `_currentRatio` + add `_targetRatio`, attach/detach `CompositionTarget.Rendering` via `EnabledChanged`, `OnRenderingTick` lerp + guard chain

**Details:**

`MainWindow` now drives the visible ghost-mode fade through a per-frame lerp pump on `CompositionTarget.Rendering` while ghost mode is enabled, with zero per-frame overhead while disabled. `_currentRatio` lerps toward `_targetRatio` (set by `_ghostMode.ProximityChanged`) via the pure `LerpRatio` helper using exponential decay `current + (target - current) * (1 - exp(-alpha * deltaSeconds))`, with terminal-state snap closing the loop at exact 0.0 / 1.0. The five existing guards (`_isDragging`, settings-window-open, `_menuOpen`, mouse-wheel direct write, contrast-skip predicate) all behave identically — drag/settings/menu guards moved verbatim into `OnRenderingTick`; `SetOpacity` and `Window_PreviewMouseWheel` direct-write paths preserved byte-for-byte. The contrast-skip predicate observes `_currentRatio > 0.0` (not the target) so visible state governs the contrast pause.

### Phase 87: Verification & performance acceptance

**Goal**: Lock in the new threading + rendering model with automated tests and human-observed smoothness — no regressions in the existing 574-test suite, new pure-helper coverage, and a manual smoothness check under sustained CPU load.
**Depends on**: Phase 86 (verification target)
**Requirements**: TEST-01, TEST-02, TEST-03, TEST-04, PERF-01
**Plans**: 2 plans

Plans:

- [x] 87-01: `LerpRatioTests` (terminal-state snap + non-snap mid-range) + `OnSampleTickTests` (4 `GhostTransition` classes) + `_isGhostMode` visibility relaxation (`private` → `internal volatile`) + `[assembly: DiscoverInternals]`
- [x] 87-02: WR-04 mid-fade toggle-off fix in `OnGhostEnabledChanged(false)` + PERF-01 manual smoothness run under 25–50% CPU load + `87-VERIFICATION.md` attestation absorbing 12 carry-forward UAT items per D-CARRY-03

**Details:**

`FuzzyClock.App.Tests/LerpRatioTests.cs` and `OnSampleTickTests.cs` lock in the pure-static seams introduced by Phases 85 and 86. WR-04 patch (`MainWindow.OnGhostEnabledChanged(false)`) clears `_currentRatio`/`_targetRatio` to 0.0 and writes `this.Opacity = _windowOpacity` when not pinned by the settings window — recovers full opacity when ghost is disabled mid-fade. ## Milestone Summary

**Decimal Phases:** None (sequential 85 → 86 → 87)

**Key Decisions:**

- **Off-thread sampling via `System.Threading.Timer`** (rationale: decouples cursor sampling from UI thread; 33 ms cadence preserved; `Interlocked` reentrancy guard avoids overlapping ticks)
- **`Dispatcher.BeginInvoke` marshalling for all UI work** (rationale: WPF thread-affinity invariants; one BeginInvoke per tick, short-circuited when no transition + no ratio change per D-08)
- **Synchronous disposal with `_timer.Dispose(WaitHandle)` + dispatcher-shutdown guard** (rationale: closes teardown race in both directions — in-flight ticks drain before Dispose returns; ticks reaching BeginInvoke after dispatcher shutdown bail at the guard)
- **Frame-driven opacity rendering on `CompositionTarget.Rendering`** (rationale: visible smoothness governed by display refresh rate, not 33 ms sampling cadence; zero overhead when ghost mode disabled)
- **Pure-static `LerpRatio` helper with terminal-state snap** (rationale: testable without WPF/timer dependency; snap preserves crisp ghost activation and `Restored` event timing at exact 0.0 / 1.0)
- **`_currentRatio` (visible) vs `_targetRatio` (sampler-set)** (rationale: contrast-skip predicate observes what the user actually sees, not the future target)
- **`internal volatile bool _isGhostMode` (Phase 87 D-SEAM-02b)** (rationale: enables direct test-side ghost-mode pre-state setup for `OnSampleTickTests` without violating Phase 85 D-06 single-owner production-side write rule)

**Issues Resolved:**

- Visible ghost-mode fade was stepwise/janky under sustained CPU contention (resolved by Phases 85 + 86)
- Mid-fade toggle-off left widget half-transparent with no recovery driver (WR-04 patch in Phase 87 Plan 02)
- Disabling ghost mode left stale `WS_EX_TRANSPARENT` style on the window (CR-01 fix in Phase 87 code review)

**Issues Deferred:**
