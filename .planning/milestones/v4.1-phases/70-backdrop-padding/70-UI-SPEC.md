## Visual States

### State 1: Normal (backdrop visible)

**Visual:** Clock content, date, and stats panel have 12px breathing room on all sides (left/right/bottom) and 8px vertical gaps between rows.

**Interaction:** No interaction changes — existing mouse hover, drag, scroll wheel, and ghost mode behaviors continue unchanged.

**Transition:** N/A (static layout change)

### State 2: Ghost mode (backdrop hidden, opacity fading)

**Visual:** Backdrop fades to `Opacity=0` when cursor is distant; content remains visible. Padding is visually invisible when backdrop is hidden.

**Interaction:** Ghost mode proximity detection continues to use `GetWindowRect` which reflects new larger dimensions. Fade zone extends from new window edges (correct behavior per RESEARCH.md).

**Transition:** Existing smooth fade (driven by `_proximityRatio` in MainWindow.xaml.cs)

### State 3: Hover (fast refresh)

**Visual:** Backdrop becomes semi-opaque (`#59000000` — existing pattern). Padding creates visible breathing room around content.

**Interaction:** Existing hover behavior continues unchanged. Padding does NOT affect hit-test boundaries (using inner margins, not `Border.Padding` on outer containers per RESEARCH.md Pattern 1).

**Transition:** Existing instant backdrop color change on `MouseEnter` event

## Layout Constraints

### Window Sizing

**Behavior:** `SizeToContent="WidthAndHeight"` (existing) causes window to auto-size to fit content. Increasing inner margins will increase window dimensions.

**Expected Growth:**
- Current approximate width: 190-224px (varies by clock type and content)
- Phase 70 width increase: +24px (12px left margin + 12px right margin)
- New approximate width: 214-248px

**Height growth:**
- Date top margin: +6px (2→8px)
- Stats top margin: +4px (4→8px)
- Stats bottom margin: +12px (0→12px)
- Total height increase: ~22px

**Impact on Features:**
- Edge snapping: Still triggers within 8px of screen edges (threshold is relative to screen bounds, not window size — per RESEARCH.md Pitfall 2)
- Ghost mode: Proximity fade zone extends from new larger window edges (correct behavior — fade should be relative to visible backdrop, not old smaller bounds)
- Contrast sampling: BitBlt samples larger footprint (correct — backdrop is larger)
- Position clamping: Clamps new larger window within monitor working area (existing logic handles this correctly per RESEARCH.md Pitfall 5)

## Open Design Decisions

### Decision 1: 12px vs 16px Padding

**Context:** RESEARCH.md identifies 12-16px range as appropriate. STATE.md flags "Backdrop padding amount: Research suggests 12-16px; needs design decision" as an open question.

**Recommendation:** **12px for Phase 70.** This doubles the current 6px padding (conservative increase). If user testing shows 12px feels cramped, 16px can be a trivial XAML change (4 numeric values) in a follow-up phase or exposed as a user preference.

**Rationale:** 12px is a safe starting point. 16px might feel too spacious on small screens (e.g. 1366x768 laptops). The change is reversible without code complexity.

### Decision 2: Symmetric vs Asymmetric Bottom Padding

**Context:** Stats panel is the last element (Grid Row 2). Current pattern uses `Margin="0,4,0,0"` (no bottom margin). Proposed Phase 70 change adds 12px bottom padding.

**Recommendation:** **Symmetric 12px bottom padding** per RESEARCH.md Open Question 2. The backdrop should feel balanced — unequal bottom padding would make the widget feel "bottom-heavy" or cramped.

**Rationale:** Visual consistency. Top/left/right use 12px; bottom should match.

### Decision 3: StatsPanel Width Constraint

**Context:** `StatsPanel` has `Width="184"` to prevent horizontal jitter when percentage text changes (e.g., "9%" → "100%"). This is INTERNAL to the panel.

**Recommendation:** **Keep `Width="184"` unchanged** per RESEARCH.md Open Question 3. The width constraint prevents text-length jitter; left/right margins are EXTERNAL spacing concerns. These are independent.

**Rationale:** Separation of concerns. If the stats panel feels too narrow after adding side margins, that's a separate layout tuning decision and can be adjusted in testing (e.g. increase to 200px).
