# Plan 12-01: Hover Fast-Refresh — MouseEnter/MouseLeave Timer Switching

## Goal

Add `Window_MouseEnter` and `Window_MouseLeave` handlers to `MainWindow.xaml.cs` that switch `_statsTimer` to a 0.5s interval on hover and restore `_statsIntervalSeconds` on leave, guarded by `StatsPanel.Visibility`.

## Context

`MainWindow.xaml.cs` already has `_statsTimer` (a `DispatcherTimer`) whose interval is managed via the `SetStatsInterval()` method using the Stop+set+Start pattern. The field `_statsIntervalSeconds` stores the user's configured rate and is the immutable source of truth during hover. The event handlers need to be wired in code-behind (inside the `ContentRendered` lambda, after `_statsTimer` is constructed) so no XAML changes are required.

## Tasks

### Task 1: Add Window_MouseEnter and Window_MouseLeave handlers

**File:** `FuzzyClock.App/MainWindow.xaml.cs`

Add two private methods to `MainWindow`. Place them after `SetStatsInterval()` and before `SetStatRowVisible()`, keeping the logical grouping of stats-timer-related methods together.

**Window_MouseEnter:**

```csharp
private void Window_MouseEnter(object sender, MouseEventArgs e)
{
    if (StatsPanel.Visibility != Visibility.Visible) return;
    if (_statsTimer == null || !_statsTimer.IsEnabled) return;
    _statsTimer.Stop();
    _statsTimer.Interval = TimeSpan.FromSeconds(0.5);
    _statsTimer.Start();
}
```

Guard 1: `StatsPanel.Visibility != Visibility.Visible` — satisfies HVRF-03 (stats hidden = no effect on timer).
Guard 2: `_statsTimer == null || !_statsTimer.IsEnabled` — do not interfere if timer is already stopped (defensive; under normal operation the timer is running whenever the panel is visible).
Action: Stop+set+Start with `TimeSpan.FromSeconds(0.5)` for immediate effect — same pattern as `SetStatsInterval()`. Do NOT assign to `_statsIntervalSeconds`.

**Window_MouseLeave:**

```csharp
private void Window_MouseLeave(object sender, MouseEventArgs e)
{
    if (StatsPanel.Visibility != Visibility.Visible) return;
    if (_statsTimer == null) return;
    _statsTimer.Stop();
    _statsTimer.Interval = TimeSpan.FromSeconds(_statsIntervalSeconds);
    _statsTimer.Start();
}
```

Guard 1: `StatsPanel.Visibility != Visibility.Visible` — no action when stats hidden.
Guard 2: `_statsTimer == null` — null check only (intentionally no `!_statsTimer.IsEnabled` guard; if panel is visible but timer somehow stopped, restoring the correct interval and restarting is still correct behavior).
Action: Stop+set+Start with `TimeSpan.FromSeconds(_statsIntervalSeconds)` — restores the user's configured rate. `_statsIntervalSeconds` is read, not written.

**Verification:** Build succeeds: `dotnet build FuzzyClock.App/FuzzyClock.App.csproj`

### Task 2: Wire MouseEnter/MouseLeave in ContentRendered

**File:** `FuzzyClock.App/MainWindow.xaml.cs`

Inside the existing `ContentRendered` lambda (in the constructor), add the event subscriptions immediately after the `if (StatsPanel.Visibility == Visibility.Visible)` block — that is, at the very end of the lambda body, after `_statsTimer` is fully constructed and conditionally started.

Add these two lines at the end of the `ContentRendered` lambda:

```csharp
this.MouseEnter += Window_MouseEnter;
this.MouseLeave += Window_MouseLeave;
```

Placement rationale: `_statsTimer` is constructed earlier in the same lambda. Wiring here guarantees the handlers are never called before `_statsTimer` exists. Using code-behind wiring avoids any XAML touch.

The `ContentRendered` lambda after this change should end with:

```csharp
            if (StatsPanel.Visibility == Visibility.Visible)
            {
                _statsTimer.Start();
                UpdateStatsDisplay();
            }

            this.MouseEnter += Window_MouseEnter;
            this.MouseLeave += Window_MouseLeave;
        };
```

**Verification:** Build succeeds and no duplicate event subscriptions exist (grep `MouseEnter` in `MainWindow.xaml.cs` — one subscription site only, plus the handler declaration).

```
dotnet build FuzzyClock.App/FuzzyClock.App.csproj
```

## Human Checkpoint

Run the app (`dotnet run --project FuzzyClock.App`) and verify all four success criteria:

**SC-1 — Hover accelerates refresh (HVRF-01):**
Ensure the stats panel is visible (right-click > Stats > Show Stats if needed). Set the interval to 3s or 10s (right-click > Stats > Update Interval) so the difference is obvious. Move the mouse over the widget. The CPU/MEM/GPU/PAG percentage values should visibly tick and update at roughly 0.5s — noticeably faster than the background rate.

**SC-2 — Leave restores configured rate (HVRF-02):**
Move the mouse away from the widget. The update cadence should slow back down to the configured interval (1s, 3s, or 10s). With a 10s interval, values should visibly stop updating every half-second and settle to infrequent updates.

**SC-3 — Hidden panel: hover has no effect (HVRF-03):**
Hide the stats panel (right-click > Stats > Show Stats to toggle off). Hover over the widget. No timer should start — right-clicking immediately after to re-show the stats panel should not show any unexpected behavior. (The timer was stopped when the panel was hidden; it must remain stopped while hovering with panel hidden.)

**SC-4 — Configured interval preserved (HVRF-01, HVRF-02, HVRF-04):**
After hovering in and out several times, right-click and check the Update Interval submenu. The checkmark must remain on the interval you set before hovering (e.g., if you set 3s, the 3s item must still be checked, not 0.5s or any other value). The interval selector must not have changed.

**Resume signal:** Type "approved" if all four checks pass, or describe which check failed and what you observed.

## Success Criteria

1. With stats panel visible, moving the mouse over the widget causes stat values to visibly update at approximately 0.5s cadence (noticeably faster than any configured interval).
2. Moving the mouse away from the widget restores the stats update cadence to the user's configured interval (1s, 3s, or 10s).
3. With stats panel hidden, hovering over the widget does not start the stats timer or produce any change in timer state.
4. The user's configured interval (1s/3s/10s) is preserved after hover — hover does not overwrite the persisted setting nor alter what the interval selector shows.
