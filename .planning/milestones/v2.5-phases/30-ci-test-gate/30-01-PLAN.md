<objective>
Add a dotnet test gate to the GitHub Actions release workflow so that a broken build cannot produce a release artifact.

Purpose: Right now, pushing a tag triggers an immediate dotnet publish regardless of test state. Any test regression in the 73-test suite would go undetected and a broken binary would be released. Adding a test gate enforces the invariant: tests must pass before a release binary is produced.
Output: Modified .github/workflows/release.yml with restore + test steps inserted before the publish step.
</objective>

  <name>Task 1: Insert restore and test steps into release.yml before publish</name>
  <files>.github/workflows/release.yml</files>
  <action>
Rewrite .github/workflows/release.yml to add two new steps between "Setup .NET" and "Publish":

1. A "Restore" step: `dotnet restore`
2. A "Test" step: `dotnet test --no-restore --configuration Release`

Also add `--no-restore` to the existing "Publish" step to avoid a redundant second restore.

The final steps order must be:
  1. actions/checkout@v4  (unchanged)
  2. actions/setup-dotnet@v4  (unchanged)
  3. name: Restore
     run: dotnet restore
  4. name: Test
     run: dotnet test --no-restore --configuration Release
  5. name: Publish
     run: >
       dotnet publish FuzzyClock.App
       -r win-x64
       -c Release
       --no-restore
       --self-contained true
       -p:PublishSingleFile=true
       -p:PublishReadyToRun=true
       -o publish/
  6. actions/softprops/action-gh-release@v2  (unchanged)

The `dotnet test --no-restore --configuration Release` command runs all four projects in FuzzyClock.slnx (both FuzzyClock.Core.Tests and FuzzyClock.App.Tests). GitHub Actions default behavior is to stop execution on the first non-zero exit code, so a test failure will prevent the Publish step from running.

Do NOT add `continue-on-error: true` to the test step — fail-fast is the entire point.
Do NOT add `--filter` or project-scoped arguments — run the full solution.
Do NOT use `--no-build` on the test step (the restore step runs but no build step exists, so test must build).
