  <behavior>
    DateFormatter.Format(string format, DateTime date) dispatches on format name:
    - "Short"   → date.ToString("ddd, MMM d")     e.g. "Fri, Mar 7"
    - "Long"    → date.ToString("dddd, MMMM d")   e.g. "Friday, March 7"
    - "Numeric" → date.ToString("M/d/yyyy")        e.g. "3/7/2026"
    - "ISO"     → date.ToString("yyyy-MM-dd")      e.g. "2026-03-07"
    - unknown   → same as "Short" (fallback)

    Method signature must accept an explicit DateTime parameter (not DateTime.Now internally)
    so tests can inject a fixed date without time-sensitivity.

    Test cases using date = new DateTime(2026, 3, 7) (Saturday):
    - Format("Short",   date) == "Sat, Mar 7"
    - Format("Long",    date) == "Saturday, March 7"
    - Format("Numeric", date) == "3/7/2026"
    - Format("ISO",     date) == "2026-03-07"
    - Format("",        date) == "Sat, Mar 7"   (fallback to Short)
    - Format("unknown", date) == "Sat, Mar 7"   (fallback to Short)
  </behavior>
