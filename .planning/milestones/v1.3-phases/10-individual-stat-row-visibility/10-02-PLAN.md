**1. Add SetStatRowVisible() helper method** (after `SetStatsInterval()` and before `ApplyFontSize()`):

```csharp
private void SetStatRowVisible(Grid row, bool visible)
{
    row.Visibility = visible ? Visibility.Visible : Visibility.Collapsed;

    // Auto-collapse: if all three rows are now hidden and the stats panel is still visible,
    // collapse the entire panel. This is a one-way trigger — re-showing a row does NOT
    // auto-show the panel (user must toggle Show Stats manually, per design).
    if (!visible
        && CpuRow.Visibility == Visibility.Collapsed
        && GpuRow.Visibility == Visibility.Collapsed
        && MemRow.Visibility == Visibility.Collapsed
        && StatsPanel.Visibility == Visibility.Visible)
    {
        SetStatsVisible(false);
    }

    // Re-clamp on show: showing a row increases StatsPanel height, potentially pushing
    // the widget off-screen if near the bottom edge. Same guard as SetStatsVisible(true).
    if (visible && StatsPanel.Visibility == Visibility.Visible)
    {
        UpdateLayout();
        if (_hasUserPosition)
        {
            var clamped = SettingsService.Clamp(
                new AppSettings { Left = Left, Top = Top, FontSize = _currentFontSize },
                ActualWidth, ActualHeight);
            Left = clamped.Left;
            Top  = clamped.Top;
        }
    }

    SaveSettings();
}
```

**Key design invariants:**
- Read `row.Visibility` (not `IsChecked`) for toggle direction — WPF auto-toggles `IsChecked` before handler fires
- Use `Visibility.Collapsed` (not `Hidden`) — `Hidden` preserves layout space in StackPanel, leaving a vertical gap
- Auto-collapse is one-directional: hiding last row triggers `SetStatsVisible(false)`, but showing a row never auto-shows the panel
- Do NOT call `SetStatRowVisible()` from `ApplySettings()` — it triggers `UpdateLayout()`+`Clamp()` which are unsafe before `Show()`
