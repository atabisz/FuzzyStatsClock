  <action>
Create `FuzzyClock.App/MonitorService.cs` as `public static class MonitorService` in the `FuzzyClock.App` namespace.

Uses `System.Windows.Forms` (already available — `UseWindowsForms=true` in csproj) and `System.Runtime.InteropServices` for Win32 P/Invoke.

**Primary method: `public static string GetCurrentMonitorKey(System.Windows.Window window)`**
1. Compute window center in device pixels: `centerX = (int)(window.Left + window.ActualWidth / 2)`, `centerY = (int)(window.Top + window.ActualHeight / 2)`.
2. Get `System.Windows.Forms.Screen screen = Screen.FromPoint(new System.Drawing.Point(centerX, centerY))`.
3. Return `GetKeyForScreen(screen)`.

**Secondary method: `public static string GetPrimaryMonitorKey()`**
- Return `GetKeyForScreen(Screen.PrimaryScreen ?? Screen.AllScreens[0])`.

**Internal method: `internal static string GetKeyForScreen(System.Windows.Forms.Screen screen)`**
- Used by FindScreenForKey in MainWindow. Returns the deduplicated, lowercased key for the given Screen object.
- Calls into the key-map cache.

**Key-map algorithm (`private static Dictionary<string, string> BuildKeyMap()`):**
- Enumerate `Screen.AllScreens`.
- For each screen, obtain its raw friendly name via `GetFriendlyNameForDevice(screen.DeviceName)`.
- If raw name is null/empty: fallback raw name = `screen.DeviceName.TrimStart('\\').TrimStart('.')`.
- Collect raw names; detect duplicates; assign suffixes: for each group of screens sharing the same raw name (case-insensitive), sort by Screen.AllScreens index and assign keys: first occurrence = `"rawname"`, second = `"rawname-2"`, third = `"rawname-3"`, etc. (1-based suffix starting at 2 for the duplicate).
- Return Dictionary mapping `screen.DeviceName` (device path, e.g. `\\.\DISPLAY1`) to its deduplicated lowercase key.

**Cache:** Store the key map in a `private static Dictionary<string, string>? _keyMap`. Invalidate (set to null) when `Screen.AllScreens.Length` changes from the cached `private static int _cachedScreenCount`. Re-build lazily on next call.

**`GetFriendlyNameForDevice(string deviceName)` using QueryDisplayConfig:**
```csharp
[DllImport("user32.dll")]
private static extern int GetDisplayConfigBufferSizes(uint flags, out uint pathCount, out uint modeCount);

[DllImport("user32.dll")]
private static extern int QueryDisplayConfig(uint flags, ref uint pathCount,
    [Out] DISPLAYCONFIG_PATH_INFO[] paths, ref uint modeCount,
    [Out] DISPLAYCONFIG_MODE_INFO[] modes, IntPtr topologyId);

[DllImport("user32.dll")]
private static extern int DisplayConfigGetDeviceInfo(ref DISPLAYCONFIG_TARGET_DEVICE_NAME request);
```

Structs (pack=4 or pack=1 per Win32 spec):
```csharp
[StructLayout(LayoutKind.Sequential, CharSet = CharSet.Unicode)]
private struct DISPLAYCONFIG_TARGET_DEVICE_NAME
{
    public DISPLAYCONFIG_DEVICE_INFO_HEADER header;
    public uint flags;
    public DISPLAYCONFIG_VIDEO_OUTPUT_TECHNOLOGY outputTechnology;
    public ushort edidManufactureId;
    public ushort edidProductCodeId;
    public uint connectorInstance;
    [MarshalAs(UnmanagedType.ByValTStr, SizeConst = 64)]
    public string monitorFriendlyDeviceName;
    [MarshalAs(UnmanagedType.ByValTStr, SizeConst = 128)]
    public string monitorDevicePath;
}

[StructLayout(LayoutKind.Sequential)]
private struct DISPLAYCONFIG_DEVICE_INFO_HEADER
{
    public uint type;    // DISPLAYCONFIG_DEVICE_INFO_GET_TARGET_NAME = 2
    public uint size;
    public uint adapterId_LowPart;
    public uint adapterId_HighPart;
    public uint id;
}

[StructLayout(LayoutKind.Sequential)]
private struct DISPLAYCONFIG_PATH_INFO { /* 72 bytes */ public ulong sourceInfo; public ulong targetInfo; public uint flags; }

[StructLayout(LayoutKind.Sequential)]
private struct DISPLAYCONFIG_MODE_INFO { /* 64 bytes */ [MarshalAs(UnmanagedType.ByValArray, SizeConst = 8)] public uint[] data; }

private enum DISPLAYCONFIG_VIDEO_OUTPUT_TECHNOLOGY : uint { Other = 0xFFFFFFFF }
```

Implementation of `GetFriendlyNameForDevice`:
1. Call `GetDisplayConfigBufferSizes(0x4 /* QDC_ONLY_ACTIVE_PATHS */, out pathCount, out modeCount)`. If non-zero return, return null.
2. Allocate `paths` and `modes` arrays of the reported sizes.
3. Call `QueryDisplayConfig(0x4, ref pathCount, paths, ref modeCount, modes, IntPtr.Zero)`. If non-zero return, return null.
4. For each path in paths, build a `DISPLAYCONFIG_TARGET_DEVICE_NAME` request with `header.type=2`, `header.size=Marshal.SizeOf<DISPLAYCONFIG_TARGET_DEVICE_NAME>()`, `header.adapterId_LowPart` and `header.adapterId_HighPart` from the path's target adapter LUID, `header.id` from the target's id.
5. Call `DisplayConfigGetDeviceInfo(ref request)`. If zero return and `monitorFriendlyDeviceName` is non-empty: correlate by checking if `deviceName` ends with the last segment of `monitorDevicePath` — or simpler: match by iterating all target device names and finding one whose `monitorDevicePath` contains the GDI device name.
6. If correlation succeeds, return `request.monitorFriendlyDeviceName.Trim()`.
7. On any exception or failure, return null (caller falls back to DeviceName).

NOTE: The LUID and id fields in DISPLAYCONFIG_PATH_INFO and DISPLAYCONFIG_MODE_INFO structs are packed differently across Windows versions. A simpler but equally correct approach: call `DisplayConfigGetDeviceInfo` for each path entry and match by checking if `monitorFriendlyDeviceName` matches a known list, or match `monitorDevicePath` GDI name against `deviceName`. Use `Contains(deviceName.Replace("\\\\", "\\"))` as the matching heuristic.

If the QueryDisplayConfig approach proves unreliable during build/test, fall back to using `screen.DeviceName` stripped of `\\.\` prefix as the key (always ASCII-safe, unique, stable within a session). This fallback still satisfies MON-01/MON-02/MON-03 — it just uses "DISPLAY1" style keys instead of "Dell U2720Q" style. Document the fallback path with a comment: `// QueryDisplayConfig unavailable — falling back to GDI device name`.
