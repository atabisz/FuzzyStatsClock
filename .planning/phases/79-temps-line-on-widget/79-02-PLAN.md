  <how-to-verify>
    From a PowerShell prompt at `c:\src\FuzzyStatsClock\`:

    ```powershell
    dotnet run --project FuzzyClock.App/FuzzyClock.App.csproj -c Release
    ```

    Widget should launch within ~5 seconds (even on hardware where TemperatureService init takes the full 5s timeout). Stats panel must be visible to see the temps line — if hidden, right-click the widget and enable "Stats".

    Walk the 22-item checklist below (7 categories). For each numbered item, visually confirm (or interact as directed). If ANY item fails, note the failure, exit the widget, and reply with the failing item number(s) + description — do NOT reply `approved`.

    **Category 1 — Baseline render (TEMP-LINE-01, TEMP-LINE-03)**

    1. Right-click the widget > Settings > Temps tab > check "Show Temps Line" (master ON). Close Settings.
    2. Within one stats-tick interval (<= 5s), a new text line appears in StatsPanel directly BELOW the "up —" / uptime line. The new line uses the SAME font, SAME size, SAME color as the uptime line above it.
    3. The rendered text uses only the friendly labels `CPU`, `GPU`, `Mobo`, `NVMe` — no raw sensor names like `Tctl/Tdie`, `Core #0`, `GPU Core`, `Hot Spot`, etc. On dev box per D-19, the expected line is `GPU 51°` (single segment; GPU reading varies with load).
    4. There is NO placeholder `(N/A)` suffix, no stray separator, no trailing whitespace visible on the rendered line.

    **Category 2 — Format shape (TEMP-LINE-02, TEMP-LINE-04)**

    5. Visible segments are joined by EXACTLY two spaces (verify via screen observation — gaps between segments should be wider than a single word-space but narrower than a tab). If only one segment is visible (dev box case), this item is trivially satisfied.
    6. Each segment ends with the degree sign `°` (U+00B0). There is NO `C` or `F` suffix after the degree sign. The rendered glyph should be a superscript small circle — NOT the ordinal indicator `º` and NOT an apostrophe.
    7. Each temperature is an INTEGER (no decimal point visible). The reading tracks reality: load the CPU or GPU briefly (e.g., open Chrome and play a YouTube video for 10 seconds) and the integer should tick upward within a few timer intervals.
    8. On dev box per D-19 + Phase 75 spike: `CPU` segment is ABSENT (PawnIO-gated), `Mobo` segment is ABSENT (PawnIO-gated), `NVMe` segment is ABSENT (`HardwareType.Storage` not enumerated). The expected line is JUST `GPU 51°` (or current GPU value). If the machine has PawnIO installed or a readable NVMe, the line will include additional segments.

    **Category 3 — Master-toggle reflow (TEMP-TAB-05 SC5)**

    9. With the temps line currently visible, right-click > Settings > Temps tab > UNCHECK "Show Temps Line".
   10. The temps line disappears IMMEDIATELY — not on the next timer tick, but within a single dispatcher frame (effectively instant). The uptime line above it shifts up to fill the gap. No empty stripe is left behind.
   11. Re-check "Show Temps Line". The temps line reappears IMMEDIATELY with the same content as before.
   12. Close Settings. Kill the widget (right-click > Quit). Relaunch via `dotnet run ...`. The temps line is visible immediately at widget launch (master toggle was persisted in `%LOCALAPPDATA%\FuzzyClock\settings.json` — Phase 78-02 already established persistence; this item confirms Phase 79 does not break it).

    **Category 4 — Per-sensor reflow (TEMP-LINE-04, TEMP-TAB-05 SC5)**

   13. With master ON and the temps line visible, open Settings > Temps tab. If the GPU checkbox is currently checked (dev-box default), UNCHECK it.
   14. The temps line re-renders immediately. On dev box: if GPU was the only segment, the line COLLAPSES (formatter returns empty -> Visibility=Collapsed). On full-hardware machines: the GPU segment disappears and other segments reflow with the 2-space separator preserved (no trailing separator, no leading separator, no `(N/A)` placeholder).
   15. Re-check GPU. The segment reappears immediately.
   16. Toggle any OTHER per-sensor checkbox (CPU / Mobo / NVMe — whichever is enabled on your hardware). Confirm the same immediate reflow behavior.

    **Category 5 — Accent color parity (TEMP-LINE-06)**

   17. Right-click the widget > Accent Color > pick a distinct color (e.g., Magenta or Amber). The uptime line above AND the temps line below change to the new accent color IN THE SAME TICK — no color mismatch, no one-tick lag between them.
   18. Right-click > Accent Color > Custom... > pick a custom RGB color distinct from the presets. Again, both uptime and temps lines change together.
   19. Set the accent back to the default (Cyan).

    **Category 6 — Auto-contrast participation (TEMP-LINE-06)**

   20. Enable Auto-Contrast via right-click > Auto-Contrast (if not already on). Move the widget over a BRIGHT desktop background (e.g., a white browser window). Both the uptime and temps lines shift toward a darker / more saturated accent in lockstep — if the uptime line color changes, the temps line color changes at the same moment.
   21. Move the widget over a BLACK/dark desktop background. Both lines shift back in lockstep. There is NEVER a frame where uptime and temps have visibly different colors.

    **Category 7 — Timer piggyback + regression sweep (TEMP-LINE-05 + stability)**

   22. Hover the mouse over the widget (enters fast-refresh 500ms interval). The temps line integer updates more frequently (every ~500ms) under hover. Move the mouse away; the widget returns to the normal 5s cadence (or whatever user has set). NO second DispatcherTimer is introduced — this is verified structurally by Plan 79-01 acceptance criteria (`grep "DispatcherTimer"` on MainWindow.xaml.cs should show no net new occurrence beyond Phase 78 baseline). Observable proxy: the widget does not introduce any new timer-related error, does not double-update, and the CPU/Mem graphs on Task Manager do not show a Phase-79-attributable spike.
