```csharp
private sealed class Win32Window : System.Windows.Forms.IWin32Window
{
    public IntPtr Handle { get; }
    public Win32Window(IntPtr handle) => Handle = handle;
}

private void MenuThemeCustom_Click(object sender, RoutedEventArgs e)
{
    var hwnd = new System.Windows.Interop.WindowInteropHelper(this).Handle;

    using var dlg = new System.Windows.Forms.ColorDialog
    {
        AllowFullOpen = true,
        FullOpen      = true,
        Color         = System.Drawing.Color.FromArgb(
                            _accentColor.A, _accentColor.R,
                            _accentColor.G, _accentColor.B)
    };

    if (dlg.ShowDialog(new Win32Window(hwnd)) == System.Windows.Forms.DialogResult.OK)
    {
        var c = dlg.Color;
        SetAccentColor(System.Windows.Media.Color.FromArgb(c.A, c.R, c.G, c.B));
    }
    // Cancel: no action — current accent color preserved
}
```

**Critical notes:**
- `AllowFullOpen = true` + `FullOpen = true`: opens with the full custom color panel expanded by default. Without these, dialog opens in compact 48-swatch mode only.
- Pre-seeding `dlg.Color` with current `_accentColor` channels: dialog opens showing the active accent color. Conversion order is ARGB for both `System.Drawing.Color.FromArgb` and `System.Windows.Media.Color.FromArgb`.
- `dlg.ShowDialog(new Win32Window(hwnd))`: HWND owner is MANDATORY. Without it, the dialog renders behind the Topmost=True widget — user sees nothing, widget appears frozen.
- On OK: `SetAccentColor()` already sets `_accentColor`, calls `ApplyTheme()`, calls `SaveSettings()` — do NOT inline these.
- On Cancel: fall through silently — `_accentColor` is unchanged.
- `System.Drawing.Color.A` from ColorDialog is always 255 (Windows color picker has no alpha control) — this is correct; widget alpha is controlled by Window.Opacity separately.

After all three edits, run `dotnet build FuzzyClock.App/FuzzyClock.App.csproj` and confirm 0 errors.
