    1. Build + run dev launch:
       ```powershell
       dotnet build FuzzyStatsClock.slnx -c Debug
       dotnet run --project FuzzyClock.App -c Debug --no-build
       ```
       Pass criteria:
       - First-paint of the widget visible within ~1 second

    Category B — Settings checkbox + persistence (DEBUG; behavior is independent of network):

    3. Open Settings → Behavior. Confirm:
       - "Check for updates on launch" checkbox is checked (default ON)
       - It clones placement / styling of the existing "Launch on startup" checkbox (or whatever the live label of `ChkAutoLaunchEnabled` is)
    4. Toggle the checkbox OFF. Close Settings. Reopen Settings. Confirm:
       - Checkbox is still OFF (immediate-persist fired)
       - Open `%LOCALAPPDATA%\FuzzyClock\settings.json` in Notepad — confirm the JSON contains `"UpdateChecksEnabled": false`
    5. Toggle the checkbox back ON. Confirm:
       - settings.json reflects `"UpdateChecksEnabled": true`
       - No exception, no widget repaint glitch
    6. Tray menu → Reset to Defaults. Confirm:
       - settings.json `"UpdateChecksEnabled"` is `true`
       - Settings → Behavior checkbox is checked again (RefreshControls fired)

    Category C — Phase 33 dual-path (DEBUG; theme + auto-contrast both run regardless of #if DEBUG):

    7. With Settings open and the checkbox visible, manually flip `UpdateText.Visibility = Visible` for the duration of this test. Easiest path: temporarily edit the XAML default to `Visible` and rebuild, OR use Visual Studio's WPF Live Visual Tree to flip Visibility at runtime, OR set `UpdateText.Text = "v9.9.9 available"; UpdateText.Visibility = Visible;` from the Immediate window.
    8. Switch theme (tray → Theme presets → Crimson, then Steel Blue, then Aurora Green). Pass criteria:
       - `UpdateText.Foreground` updates to the new accent on EACH switch
       - No flicker, no stale color
    9. Drag the widget over a high-contrast background (white desktop with black text, e.g. Notepad with default theme). Wait for auto-contrast trip (~500ms). Pass criteria:
       - `UpdateText` flips to black/white along with every other accent-colored element
       - No element lags behind (would indicate Phase 33 dual-path miss)
    10. Restore `UpdateText.Visibility = Collapsed` after this category if the XAML was hand-edited.

    Category D — Mid-session toggle OFF cancels in-flight (smoke test, DEBUG-honest):

    11. With the Phase 33 forcing from step 7 still active OR with a temporarily-disabled `#if DEBUG` short-circuit (locally only — DO NOT commit this), launch and immediately open Settings, uncheck the box. Pass criteria:
        - `UpdateText.Visibility` flips to Collapsed within ~50ms (no waiting for the 5s timeout)
        - settings.json now contains `"UpdateChecksEnabled": false`
    12. Confirm by step-debugger or `Debug.WriteLine` that `_updateService.CancelInFlight()` was called from the OpenSettings handler.

    Category E — Real v4.4 settings.json absent-field upgrade (PERS-05 live):

    13. Locate a real v4.4 backup of `%LOCALAPPDATA%\FuzzyClock\settings.json` (or hand-edit one to remove the `UpdateChecksEnabled` key entirely). Place it in `%LOCALAPPDATA%\FuzzyClock\settings.json`.
    14. Launch v4.5 dev build. Open settings.json after launch. Pass criteria:
        - File now contains `"UpdateChecksEnabled": true` (init default applied during deserialization, persisted by SaveSettings on first settings change OR retained-as-default on next deserialize round-trip — either is acceptable; the in-memory `_settings.UpdateChecksEnabled` MUST be `true` regardless)
        - Settings → Behavior checkbox renders as checked

    Category F — Near-edge re-clamp (UI-05):

    15. Drag the widget so its bottom edge is within ~13px of the screen's WorkingArea bottom (the widget bottom should be flush with the taskbar top). Use Phase 33 forcing from step 7 to flip `UpdateText.Visibility = Visible`. Pass criteria:
        - The widget jumps up by ~13px so the new UpdateText line is fully on-screen
        - The widget's `Top` value (visible in Visual Studio's WPF Live Visual Tree) decreased

    16. ONLY if a fresh release-config publish is built (`dotnet publish FuzzyClock.App -c Release -p:PublishSingleFile=true -r win-x64 --no-self-contained`):
        - Launch the published exe on a Windows machine with default Defender + SmartScreen
