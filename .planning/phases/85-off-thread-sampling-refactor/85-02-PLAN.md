<objective>
Convert the cross-thread-read config fields in `GhostModeController` to `volatile` backing fields per D-10 and D-11, so the sampler thread (introduced in Plan 03) sees UI-thread writes without torn reads or stale caches. **No threading changes in this plan** — `OnTimerTick` still runs on the dispatcher; this plan is purely a field-shape change ahead of the timer swap.

Purpose: With Plan 03 installing a thread-pool timer, any read of `_isEnabled`, `_useCtrl/_useAlt/_useShift`, or `_ghostFadeRadiusPx` from the sampling thread must observe writes performed on the UI thread. `volatile` provides the cheapest correct primitive for these access shapes (rare UI writes, frequent sampler reads, single atomic stores for `bool`/`int`-aligned types). Doing the field conversion as its own plan keeps the diff reviewable and lets the threading swap in Plan 03 be a pure mechanism change rather than mixing field shapes with timer types.

Output: `GhostModeController.cs` declares `private volatile bool _isEnabled`, `private volatile bool _useCtrl/_useAlt/_useShift`, and `private volatile int _ghostFadeRadiusPx`. `IsEnabled` becomes a manual property over `_isEnabled`. `UpdateModifierConfig`, `IsEnabled` setter, and `GhostFadeRadiusPx` setter perform single atomic stores. `OnSampleTick` (introduced in Plan 01) snapshots each volatile field once at the top into a local. All existing tests pass unchanged.
</objective>
