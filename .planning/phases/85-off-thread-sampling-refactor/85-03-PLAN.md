<objective>
Swap `DispatcherTimer` for `System.Threading.Timer` so cursor sampling no longer competes with WPF layout/input/render on the UI thread (SAMP-01). Wrap the tick callback in an `Interlocked.CompareExchange` reentrancy guard (D-02). Capture the window's dispatcher once at `Initialize` (D-09 / `<specifics>`). After the pure `OnSampleTick` returns, marshal all UI-touching work — `WS_EX_TRANSPARENT` toggle, `ProximityChanged` raise, `Restored` raise, `Activate()` call — through a single `_dispatcher.BeginInvoke` per tick when work is required (D-07), skipping `BeginInvoke` entirely on `transition=None && !ratioChanged` (D-08). Guard `BeginInvoke` with `_dispatcher.HasShutdownStarted/HasShutdownFinished` (D-09).

Purpose: This is the threading-mechanics swap that delivers SAMP-01..04 and preserves SEM-01/02/05 byte-for-byte. The pure-logic seam from Plan 01 is unchanged; the volatile fields from Plan 02 give the sampler thread coherent reads of UI-managed config. Plan 04 will follow with synchronous disposal.

Output: `GhostModeController.cs` declares `private readonly System.Threading.Timer _timer;`, captures `_dispatcher` at `Initialize`, replaces `_restoreTimer` start with `_timer = new System.Threading.Timer(OnSampleThreadTick, null, 0, 33);` (or equivalent — exact spelling per `<action>`), and routes UI work through `_dispatcher.BeginInvoke`. The `OnSampleThreadTick` callback runs on the thread pool, gathers Win32 inputs, calls `OnSampleTick`, conditionally bundles UI-touching work into a single `BeginInvoke`. `Dispose()` is intentionally NOT changed in this plan — Plan 04 owns the synchronous disposal swap (this plan keeps a placeholder `_timer.Dispose()` so the file compiles; Plan 04 hardens it).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Sampler thread → UI thread | Timer callback runs on thread pool; UI work crosses via `Dispatcher.BeginInvoke`. Trust: every UI-touching write is on the UI thread (WPF affinity preserved). |
| UI thread → sampler thread | Settings writes (`IsEnabled`, `UpdateModifierConfig`, `GhostFadeRadiusPx`) cross via volatile fields (Plan 02). Trust: sampler reads see UI writes without torn reads. |
| Application shutdown → tick callback | Late tick may fire after `Application.Current.Shutdown()` begins. Trust: D-09 `HasShutdownStarted/HasShutdownFinished` guard + Plan 04's synchronous disposal close the window. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-85-07 | Tampering | Concurrent tick callbacks corrupting `_lastProximityRatio` / `_isGhostMode` | mitigate | D-02 `Interlocked.CompareExchange(ref _tickInFlight, 1, 0)` reentrancy guard ensures at most one thread inside the tick logic; `try/finally` releases the guard on every path |
| T-85-08 | Tampering | UI work executing on sampler thread (WPF/Win32 thread-affinity violation) | mitigate | D-07 — all UI work goes through `_dispatcher.BeginInvoke`; the lambda body is the only place that touches `WS_EX_TRANSPARENT`, raises events, or calls `Activate()` |
