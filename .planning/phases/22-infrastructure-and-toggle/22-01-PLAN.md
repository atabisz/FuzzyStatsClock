    Make exactly six targeted additions to MainWindow.xaml.cs. Follow each pattern precisely — these are not approximations; exact code is verified against source line numbers in 22-RESEARCH.md.

    **1. ApplySettings() — direct Visibility assignment (after PagRow line ~134):**
    ```csharp
    UptimeText.Visibility = s.UptimeVisible ? Visibility.Visible : Visibility.Collapsed;
    ```
    CRITICAL: Direct assignment, NOT `SetUptimeRowVisible(s.UptimeVisible)`. Calling SetUptimeRowVisible here triggers UpdateLayout()+Clamp() before Show(), producing ActualHeight=0 and corrupted window position (P11 pitfall). All existing rows use direct assignment here; match that pattern.

    **2. SaveSettings() — add to inline AppSettings record construction (after PagVisible line ~179):**
    ```csharp
    UptimeVisible = (UptimeText.Visibility == Visibility.Visible),
    ```
    CRITICAL: This must be added in this same task as the AppSettings field (or at latest this task). Omitting it causes the init default (true) to overwrite the user's saved choice on every restart — silent, invisible bug.

    **3. ContextMenu_Opened() — IsChecked sync (after MenuPagVisible sync line ~309):**
    ```csharp
    MenuUptimeVisible.IsChecked = (UptimeText.Visibility == Visibility.Visible);
    ```
    WPF auto-toggles IsChecked on every click for IsCheckable items. Without this sync, the checkmark diverges after one open-close cycle (P10 pitfall).

    **4. MenuUptimeVisible_Click handler — read Visibility, not IsChecked:**
    ```csharp
    private void MenuUptimeVisible_Click(object sender, RoutedEventArgs e)
        => SetUptimeRowVisible(UptimeText.Visibility != Visibility.Visible);
    ```
    Read Visibility (the ground truth), not IsChecked (which WPF has already toggled). Identical pattern to MenuCpuVisible_Click.

    **5. SetUptimeRowVisible() — full method with UpdateLayout+Clamp guard:**
    ```csharp
    private void SetUptimeRowVisible(bool visible)
    {
        UptimeText.Visibility = visible ? Visibility.Visible : Visibility.Collapsed;

        // Re-clamp on show: UptimeRow adds ~15px; widget near bottom edge would slide off screen.
        if (visible && _hasUserPosition)
        {
            UpdateLayout();
            var clamped = SettingsService.Clamp(
                new AppSettings { Left = Left, Top = Top, FontSize = _currentFontSize },
                ActualWidth, ActualHeight);
            Left = clamped.Left;
            Top  = clamped.Top;
        }

        SaveSettings();
    }
    ```
    Clamp is only called when showing (not hiding) to avoid unnecessary layout calls. Guard on _hasUserPosition matches SetStatRowVisible() pattern (lines 455-465 per research).

    **6. ApplyTheme() — add UptimeText to accent color coverage (after PagText.Foreground line ~677):**
    ```csharp
    UptimeText.Foreground = brush;
    ```
    Reuse the `brush` variable already in scope at the top of ApplyTheme() — no new SolidColorBrush needed. Without this, UptimeText stays white when a non-white accent is active.

    Place SetUptimeRowVisible() near the other Set*Visible methods (around line 438). Place MenuUptimeVisible_Click near other row click handlers (around line 347).
