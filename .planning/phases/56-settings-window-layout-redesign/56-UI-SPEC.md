## Spacing Scale

This phase operates in WPF logical pixels (device-independent). The 8-point grid maps
directly to WPF margin/padding values. All spacing tokens are multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inner ring outer padding (see exception below) |
| sm | 8px | Compact inter-section gaps (theme cards bottom margin, control Grid top margin) |
| md | 16px | Standard row spacing in Stats/Behavior tabs |
| lg | 24px | Tab StackPanel outer margin (12px each side = 24px total) |
| xl | 32px | Not used in this phase |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions — the following two XAML values are pre-existing constants that are explicitly
excluded from the 4px grid contract. They are not spacing tokens and must not be treated
as grid violations:

- `Padding="1"` on the ring outer Border: this is a 1px visual-effect constant that
  creates a selection-ring gap between the outer and inner card borders. It is a rendering
  artifact, not a layout spacing value, and is therefore not subject to the multiple-of-4
  grid rule.
- `Margin="0,8,10,0"` on control Grid rows: the 10px right component is a fixed
  label-to-control alignment inset, not a section gap or layout spacing token. It is a
  visual-alignment constant carried over from the original design and is therefore not
  subject to the multiple-of-4 grid rule.

Source: RESEARCH.md (Proposed Spacing Reductions table), SettingsWindow.xaml direct measurement.

## Component Inventory

The following existing components are modified in this phase. No new components are added.

### Theme Card (compact form — CHANGED)

Each of the five theme preset cards is reduced from a 64px-tall card to a 40px-tall card.

**Before (current):**
```xml
<Border x:Name="RingTheme*" BorderThickness="0" CornerRadius="6"
        Padding="2" Margin="0,0,6,0">
    <Border Width="60" Height="64" Background="#FF2D2D2D" CornerRadius="4" ...>
```

**After (target):**
```xml
<Border x:Name="RingTheme*" BorderThickness="0" CornerRadius="4"
        Padding="1" Margin="0,0,6,0">
    <Border Width="60" Height="40" Background="#FF2D2D2D" CornerRadius="4" ...>
```

Constraints:
- x:Name values (RingThemeMidnight, RingThemeNeon, RingThemeGhost, RingThemeWarm,
  RingThemeTerminal) must not change — code-behind sets BorderThickness/BorderBrush on
  these named elements.
- Width="60" must not change — five cards at 60px width + four 6px gaps = 324px, fits the
  ~456px content area.
- Inner content (Ellipse 20px + Margin bottom 4px + TextBlock ~13px = 37px) must remain
  unchanged. Height="40" provides 3px slack above/below — do not go below 40.

Source: RESEARCH.md (Proposed Compact Card Structure), SettingsWindow.xaml lines 61–78.

## Interaction Contracts

### Theme Card Selection

- Hover: inner Border Opacity transitions to 0.75 (via existing Style.Trigger — unchanged).
- Click: fires ThemeXxx_Click handler — code-behind sets BorderThickness="2" and
  BorderBrush on the corresponding RingTheme* Border to show the selection ring.
- Active card ring: 2px solid BorderBrush (color set from code-behind per theme accent).
- No change to hover or click behavior in this phase — only geometry changes.

### No New Interactions

This phase introduces no new interactive states, focus patterns, keyboard shortcuts,
or animation behaviors. All interactions in the Appearance tab remain identical to v3.5.
