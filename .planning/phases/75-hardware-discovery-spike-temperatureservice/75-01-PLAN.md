    Then create the throwaway enumerator under `scratch/Enumerator/` with the exact code from 75-RESEARCH.md Section 2.3. This is a one-shot console app referencing LibreHardwareMonitorLib 0.9.6 — NOT part of the solution file (`FuzzyClock.slnx`). Do NOT add it to the solution. The program:

    1. Creates a `Computer` with `IsCpuEnabled = true, IsGpuEnabled = true, IsMotherboardEnabled = true, IsStorageEnabled = true` (all others false — matches service runtime posture per STACK.md).
    2. Times `Computer.Open()` once (cold call — milliseconds).
    3. Walks the full hardware tree recursively, printing `[HardwareType] Name (Id=...)` plus every sensor's `SensorType`, `Name`, `Value?.ToString() ?? "null"`, with SubHardware indented one level.
    4. Times 20 consecutive `computer.Accept(new UpdateVisitor())` calls at ~2s spacing (use `await Task.Delay(TimeSpan.FromSeconds(2))`).
    5. Prints `Update() mean=X.X min=Y max=Z ms` where mean is `timings.Average():F1`.
    6. Calls `Computer.Close()` before exit.
    7. The `UpdateVisitor` is a sealed class implementing `IVisitor` with `VisitComputer -> c.Traverse(this)`, `VisitHardware -> h.Update(); foreach (var s in h.SubHardware) s.Accept(this)`, `VisitSensor` and `VisitParameter` as empty — per the template in 75-RESEARCH.md Section 2.3.

    Initialize via `dotnet new console -n Enumerator -o scratch/Enumerator`, then `dotnet add scratch/Enumerator/Enumerator.csproj package LibreHardwareMonitorLib --version 0.9.6`. Build with `dotnet build scratch/Enumerator/Enumerator.csproj` to confirm it compiles (do NOT run yet — PawnIO is still installed; that happens in Task 2).

    ANTI-PATTERN: Do NOT add the scratch project to FuzzyClock.slnx. Do NOT commit the enumerator's source files. Only the `.gitignore` entry and the later spike report are committed.

